# Prompt 11 — Admin device checks

Automated compilation and JVM tests do not exercise live Firestore permissions, multiple devices, or notification delivery.

1. Sign in as an admin. Open Dashboard, Bookings, Workshops, and Services. Each screen verifies the current Firebase user's server-side profile role on start. A customer, missing profile, or signed-out user must return to Login with the task cleared. Offline verification fails closed; reconnect and sign in again.
2. Seed demo data, cancel the confirmation first, then confirm. Expect 6 Dhaka workshops and 10 services. Repeat: stable IDs must avoid duplicates and earned rating aggregates must remain. Customer Home title long-press must do nothing. Refresh customer Home to see the seed.
3. Create a service with price, duration, category and comma-separated keywords; edit it. Reject blank name/category, invalid/nonfinite price, and invalid duration. Add that service to a workshop using the multi-select dialog. Cancel the dialog once to verify choices are not committed.
4. Add/edit a workshop, including hours, phone, address, description and Featured switch. Check overnight hours if needed. Reject equal/out-of-range hours and missing required data. Refresh customer Home: featured workshop sorts first with its badge. Open details and verify offered service, price, duration, dial action and booking availability.
5. Delete a service/workshop: cancel first, then confirm. Existing bookings retain their saved names/details; deleted catalog items cannot be newly booked. Remove deleted service IDs from workshop offerings if necessary.
6. Create customer bookings. In Admin Bookings, combine each status filter with a workshop Spinner selection. Tap a row and verify customer name/phone, dialer, car, service, time, note, pickup request, price and commission.
7. Move PENDING → CONFIRMED → IN_PROGRESS → READY → COMPLETED. Only the permitted next actions should appear. Cancellation is offered only for PENDING/CONFIRMED, with confirmation. Repeat concurrently on two admin devices: stale transitions must fail rather than overwrite newer status. Refresh after a conflict. Cancelled slots must be bookable again.
8. Keep customer My Bookings open on another signed-in device. Verify status updates, notification text/deep link, confirmation reminder and cancellation alarm removal through the existing sync flow. Background updates use the previously implemented bounded/periodic sync; they are not instant push messaging.
9. Compare dashboard statistics against bookings: today's appointments, all pending, completed appointments dated this month, and their stored commission sum. Dates and chart bins use Asia/Dhaka. The seven bars count appointment dates, including cancelled appointments, and include zero days. Dashboard has an explicit refresh button.
10. Logout from Dashboard. Back must not reopen admin tools. Reopen and verify Login. Use a narrow phone, keyboard, and large font to check scrolling and forms.

The app checks admin role before reads and inside every admin write transaction. Production Firestore Security Rules must independently enforce admin privileges; client checks do not replace server access control. No rule deployment or live backend testing was performed by this prompt.
